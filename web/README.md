# AI Story EP01-01 — 시각 조사 프로토타입

설치·빌드·외부 API 없이 실행되는 HTML/CSS/Vanilla JavaScript 게임입니다. **제공된 WebP 이미지 9개를 연결했습니다.** 모두 1024×680이며 원본 파일을 수정하지 않고 사용합니다. 표지·장면·증거는 원본 비율을 유지하며, 이미지 로드 실패 시에도 대체 표시로 플레이할 수 있습니다. 이전 SVG 일러스트는 새 화면에서 사용하지 않습니다.

## 로컬 실행

저장소 루트에서:

```sh
python3 -m http.server 8080 --directory web
```

브라우저에서 http://localhost:8080 을 엽니다. 종료는 터미널에서 Ctrl+C.

## 플레이 흐름

시작 → 현관에서 택배 가져오기 → 실내에서 상자 열기 → 택배 내부 조사 → 사진 앞·뒷면, 펼친 쪽지, USB 수집 → 증거 연결 → 화재 기사 → **EP01-01 조사 완료**.

- 사진: 물건 또는 버튼을 눌러 양면을 회전합니다. 뒷면을 처음 볼 때 해당 증거를 수집합니다.
- 쪽지: 접힌 물건 또는 펼치기 버튼을 누르면 안쪽 이미지와 원문이 나타납니다. 펼쳐야 수집됩니다. 다시 접어도 읽은 증거는 유지됩니다.
- USB: 100~300%를 50% 단위로 확대·축소하고 스크롤해 관찰합니다. 확대 전 관찰 위치를 유지하며 원래 크기로 복원할 수 있습니다. 연결 기능은 없습니다.
- 인벤토리: 증거 원본의 썸네일로 다시 엽니다. 사진 앞면·뒷면은 각각 해당 면을, 쪽지 기록은 읽은 안쪽을 엽니다.
- 추리: 증거 4개 수집 후 **가족사진 뒷면 + 쪽지 안쪽**을 연결합니다. 이전의 가족사진 앞면+쪽지는 정답이 아닙니다. 오답은 제한 없이 다시 시도합니다.
- 완료: 기사를 확인한 후 완료 화면으로 이동합니다. 증거를 재검토해도 완료 기록은 남으며 완료 화면으로 돌아갈 수 있습니다. 다음 회차는 구현하지 않았습니다.

추리는 쪽지가 기사 검색을 지시한 것으로 해석하지 않습니다. 사진의 ‘기록과 사실’과 쪽지의 ‘직접 확인’을 연결한 뒤, 주인공이 공개 기사를 조사하는 방향을 정합니다. 발신인·화재 원인·흑막·USB 내용은 확정하지 않습니다.

## 정확한 원문과 이미지 연결

원문은 `js/story.js`의 `quotes`에 정의됩니다.

- 사진 뒷면: “기록은 사라져도, 사실은 사라지지 않는다.”
- 쪽지 안쪽 (두 줄):

```text
당신의 부모님에 관한 기록입니다.
믿지 않아도 좋습니다. 직접 확인하십시오.
```

조사 화면·접근성용 이미지 설명·추리 선택지는 이 원문을 공유합니다. 이미지에 들어갈 실제 글자도 원문과 대조해야 합니다.

**[이미지 9개 목록과 연결 안내](assets/images/ep01-01/README.md)**에서 연결된 파일을 확인할 수 있습니다. `js/assets.js`의 9개 항목은 모두 `ready: true`입니다. 이미지를 교체할 때는 같은 파일명을 사용하거나 `file` 값을 수정하세요. 미제공 항목으로 전환하려면 `ready: false`로 설정합니다. 파일 로드에 실패해도 대체 표시로 게임을 계속할 수 있습니다. 썸네일은 별도 제작 없이 원본을 축소합니다.

## 저장과 기존 데이터

새 저장 키는 `ai-story:ep01-01:v2`입니다. 장면·증거·추리 해금·기사 확인·완료·사진 방향·쪽지 펼침 상태·열려 있는 조사 화면을 저장합니다. USB 확대 배율은 다시 열 때 100%로 돌아갑니다.

새 저장이 없고 v1 저장이 있으면 자동 이전합니다.

- 기존 `doorstep`: 현관 유지
- 기존 `room`: 택배 내부로 이동, 수집 증거 유지
- 기존 `ending`: 기사 화면으로 이동, 기사 도달 기록 유지
- 조사 중이던 기존 추리 해금은 새로운 원문 기준으로 다시 판정

이전 후 v2에 저장합니다. 완료 후 이어하기는 완료 화면을 복원합니다. ‘처음부터’ 확인 창에서 초기화하면 v2를 초기 상태로 저장하고 이전 v1 저장도 삭제합니다. 취소하면 진행을 유지합니다. 손상된 JSON은 새 게임으로 복구합니다. 저장이 차단되면 경고를 표시하고 현재 페이지 메모리에서 플레이합니다 (새로고침 복원은 불가).

## 파일 구조

| 파일 | 역할 |
| --- | --- |
| `index.html` | 페이지 구조, 증거 조사·초기화 대화상자 |
| `css/style.css` | 장면별 화면, 회전·펼침·확대, 반응형·동작 줄이기 |
| `js/story.js` | 장면·원문·증거·추리 정답·기사·완료 데이터 |
| `js/assets.js` | 9개 로컬 이미지 파일명·연결 상태·접근성 설명 |
| `js/state.js` | 저장 검증·이전·추리 조건 판정 |
| `js/game.js` | 화면 전환·조사 조작·인벤토리·자동 저장 |
| `assets/images/ep01-01/` | 연결된 WebP 이미지 9개와 연결 규격 |
| `tests/state.test.mjs` | 원문·추리·기존 저장 이전·완료 복원 회귀 테스트 |
| `TESTING.md` | 이번 검증 결과와 수동 회귀 절차 |

키보드: Tab으로 이동, Enter/Space로 버튼·체크박스 조작, Escape로 조사 창 닫기, 확대 영역에서 화살표로 스크롤. 조사 창을 닫으면 해당 조사 버튼으로 초점이 돌아갑니다. OS의 동작 줄이기 설정에서는 회전·펼침 애니메이션을 생략합니다.

## GitHub Pages 배포

1. GitHub 저장소 Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 설정합니다.
2. 배포할 준비가 되면 Actions에서 **Deploy game to GitHub Pages**를 수동 실행합니다. 커밋·푸시로는 배포가 시작되지 않습니다.
3. 성공한 배포의 `github-pages` 환경 URL에서 게임을 엽니다.

`.github/workflows/pages.yml`은 `workflow_dispatch`만 사용하며, 수동 실행 시 `web/`를 배포 대상으로 사용합니다. 상대 경로를 사용해 프로젝트 경로에서도 동작합니다. 현재는 미배포 상태이며 GitHub 원격 저장소 생성·연결·푸시를 진행하지 않았습니다.
