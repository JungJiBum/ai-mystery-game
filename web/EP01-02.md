# EP01-02 「12년 전의 사고」 개발 안내

## 원고 기준

Obsidian의 `AI Story/EP01-02_12년 전의 사고.md`를 읽고 구현했습니다. 원고 상태는 ‘초고 — 검토 필요’, 블로그 미발행입니다. 원고는 수정하지 않았으며 전체 원고를 저장소로 복사하지 않았습니다. 관련 인용과 전개만 별도 스토리 데이터에 반영했습니다.

- 기사 속 전기 설비 이상은 **당시 발표된 사고 경위**로 표시합니다. 다른 기사에서는 정확한 원인을 조사 중이라고 하므로 실제 화재 원인은 확정하지 않습니다.
- 연구소 고유명·삭제된 페이지의 실제 주소는 원고에 없습니다. 이를 새로 만들지 않고 ‘기사 속 연구소 + 기록실’ 검색과 삭제된 주소 안내를 게임 내 HTML로 구현합니다. 실제 인터넷 검색이나 외부 전송은 없습니다.
- 안내판 판독은 `…기록실`, 검색 미리보기와 공식 보도자료 인용도 원고와 일치합니다.
- 범인·USB 내용·후배 연구원의 정체를 설정하지 않습니다. USB는 연결하지 않은 미확인 증거로 유지합니다.
- 완료 화면은 ‘원본은 지금 어디에 있을까’라는 의문과 EP01-03 「존재하지 않는 기록」 제목만 제시합니다. EP01-03으로 진입하는 경로나 버튼은 없습니다.

## 플레이

1. EP01-01 기사 확인 후 조사를 완료합니다.
2. 완료 화면의 EP01-02 시작 버튼을 누릅니다.
3. 당시 화재 기사를 읽고 가족사진과 화재 현장 사진을 비교합니다.
4. ‘가족사진 안내판 확대 판독’으로 `…기록실`을 발견합니다.
5. 기사 속 연구소를 대상으로 `기록실`을 검색합니다. 잘못된 검색은 재시도할 수 있습니다.
6. 미리보기의 페이지를 열어 삭제된 주소임을 확인합니다.
7. 공식 보도자료의 내부 기록·원본 보존 문구를 기록합니다.
8. 네 단서를 확인한 후 **삭제된 페이지의 미리보기 + 공식 보도자료의 보존 문구**를 연결합니다.
9. 기록을 정리하고 EP01-02를 완료합니다. 단서 재열람과 회차별 초기화를 지원합니다.

제공된 화재 외관·검색 화면·보도자료 PNG는 참고용으로 연결했습니다. 기관명은 가리고 검색·보도자료의 글자는 비노출 처리합니다. 이미지의 기관명·날짜·문구는 원고 설정이나 정답이 아닙니다. 검색·자료 열람은 기존 HTML을 기준으로 유지하며 이미지가 없어도 플레이할 수 있습니다. 기존 가족사진은 그대로 재사용하므로 안내판 글자의 실제 픽셀 확대가 아니라 원고 기반 판독 텍스트를 보여 줍니다. 이미지 연결 방법은 [자산 안내](assets/images/ep01-02/README.md)를 참고하세요.

## 회차 이동과 수명 관리

- `#ep01-01`, `#ep01-02`의 해시 주소를 사용합니다. 없는 회차나 잘못된 해시는 EP01-01로 정규화합니다.
- 새 EP01-02는 EP01-01 저장을 기존 `GameState.normalize`로 검증한 뒤 완료·기사 확인·네 증거를 확인해야 시작할 수 있습니다. 미완료라면 안내 화면으로 진입합니다.
- 브라우저 뒤로/앞으로는 회차를 바꾸며, 각 회차 안의 단계는 그 회차 저장으로 복원합니다. 각 단계가 별도의 브라우저 방문 기록을 만들지는 않습니다.
- 회차를 떠날 때 현재 메모리 상태를 보존하고, 열린 조사 창·초기화 창을 닫고 리스너와 USB 포인터 캡처를 정리합니다. 다시 돌아오면 같은 회차의 상태로 복원합니다.
- 새로고침으로 앱을 다시 시작하면 저장된 회차의 이어하기 화면이 나타납니다.

## 저장 규격과 초기화

| 회차 | 현재 저장 키 | 이전 처리 |
| --- | --- | --- |
| EP01-01 | `ai-story:ep01-01:v2` | 기존 `ai-story:ep01-01:v1` 이전 로직 유지 |
| EP01-02 | `ai-story:ep01-02:v1` | 별도 검증기, EP01-01 이전 규칙을 적용하지 않음 |

EP01-02 시작 시 사본으로 저장하는 전회차 기록:

```json
{
  "sourceEpisode": "ep01-01",
  "sourceSaveVersion": 2,
  "completed": true,
  "articleRead": true,
  "found": ["photo", "back", "note", "usb"]
}
```

이 사본은 EP01-02의 `inherited`에 들어갑니다. 이번 회차의 `found`는 `article`, `sign`, `trace`, `press`를 별도로 관리합니다. 전회차 증거를 이번 회차 인벤토리에 합치지 않습니다. 화면 조작 상태나 USB 내용·연결 여부를 새로 추론해 인계하지 않습니다.

- EP01-01을 초기화하면 기존과 같이 EP01-01 v2를 초기 상태로 저장하고 EP01-01 v1을 삭제합니다. EP01-02는 건드리지 않습니다.
- EP01-02를 초기화하면 이번 회차 진행과 완료만 지우고 `inherited` 사본을 유지합니다. EP01-01 저장은 건드리지 않습니다.
- EP01-02 시작 후 EP01-01을 다시 플레이해도 기존 EP01-02 저장·이어하기는 유지됩니다. 새로고침 후에도 저장된 사본을 검증해 복원합니다.
- 저장 차단 시 현재 페이지의 메모리로 회차를 오가며 플레이할 수 있습니다. 새로고침 후 복원은 불가능합니다.
- 손상된 EP01-02 저장은 새로 검증한 EP01-01 완료 기록이 있으면 새로 시작하고, 없으면 잠금 안내를 표시합니다.

## 코드 구조

- `js/episodes.js`: 회차 목록·해시 해석
- `js/router.js`: 해시 이벤트·회차 마운트/정리·메모리 인계
- `js/storage.js`: 저장 키·전회차 읽기·EP01-02 읽기/쓰기/초기화
- `js/game.js`: 기존 EP01-01의 기능을 `Episode01.mount()`로 감싸고 다음 회차 버튼과 정리 함수를 추가
- `js/episodes/ep01-02/story.js`: 원고 기준 장면·인용·단서·완료 데이터
- `js/episodes/ep01-02/assets.js`: 참고 이미지 3종의 경로·크기·설정 불일치 표시 정책
- `js/episodes/ep01-02/state.js`: 선행 기록·장면 순서·검색·단서·완료 검증
- `js/episodes/ep01-02/game.js`: 독립 화면·조사·회차 초기화
